# Windows support

OptMem runs on native Windows in PowerShell; WSL is not required. Windows uses
the same append-only store format as Linux and macOS.

## Prerequisite

Python 3.7 or newer must be available through `py -3` or `python`:

```powershell
py -3 --version
```

## Install

```powershell
irm https://raw.githubusercontent.com/doeixd/OptMem/main/install.ps1 | iex
```

To inspect the installer first:

```powershell
irm https://raw.githubusercontent.com/doeixd/OptMem/main/install.ps1 -OutFile install-optmem.ps1
Get-Content .\install-optmem.ps1
powershell -ExecutionPolicy Bypass -File .\install-optmem.ps1
```

The installer downloads and validates:

```text
$HOME\.optmem\memo       Python tool
$HOME\.optmem\memo.cmd   Windows launcher
```

It then initializes `$HOME\.optmem\memory` and prints a copyable agent
instruction block. Re-running the installer updates the tool and launcher
without changing memories or configuration.

## Verify

```powershell
& "$HOME\.optmem\memo.cmd" doctor
```

`doctor` shows the executable, Python version, current Git origin, active
scope, project/global store paths, and optional FFF status. It does not write
anything.

## Run commands

Use the launcher by path:

```powershell
& "$HOME\.optmem\memo.cmd" wake
& "$HOME\.optmem\memo.cmd" note "first project memory"
& "$HOME\.optmem\memo.cmd" --global note "true in every project"
```

Or add the directory to `PATH` for the current PowerShell session:

```powershell
$env:Path += ";$HOME\.optmem"
memo doctor
```

The PATH change is optional. Agent instructions generated by `memo init` use a
fully qualified PowerShell command and work without it.

See [AGENT_SETUP.md](AGENT_SETUP.md) for the first agent session, memory
selection, recall, and subagent guidance.

FFF-powered typo-tolerant recall is optional and requires Python 3.10+:

```powershell
py -3 -m pip install fff-search
memo recall --fuzzy "aproximate memry"
```

Exact `memo recall <regex>` continues to work without FFF.

## Override scoping

To pin all commands to an explicit store instead of project/global scoping:

```powershell
$env:MEMORY_DIR = 'C:\path\to\memory'
memo wake
```

That assignment lasts for the current PowerShell process. Remove it with:

```powershell
Remove-Item Env:MEMORY_DIR
```

## Locking

On POSIX, OptMem uses `fcntl.flock`. On Windows it locks byte zero of the
shared `.lock` file with `msvcrt.locking` and waits with bounded backoff when
another process is writing. The file is opened without truncation, so
parallel agent sessions serialize their updates safely.

## Troubleshooting

- Script execution is disabled: use the `powershell -ExecutionPolicy Bypass
  -File` review-first command above, or use the `irm ... | iex` form.
- `memo` is not recognized: call `& "$HOME\.optmem\memo.cmd"` directly or add
  the directory to the current session's `PATH`.
- The wrong store is active: run `memo doctor`, then check `MEMORY_DIR`, the
  current directory, and `Git origin`.
- Python opens the Microsoft Store: install Python from
  [python.org](https://www.python.org/downloads/windows/) or configure an
  existing Python so `py -3` works.
- Fuzzy recall fails: run exact recall, or reinstall `fff-search` with the same
  Python selected by the installer.
